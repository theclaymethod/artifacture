# Verification explainer (understando trust map)

Scope: the default look of trust-map explainers in visual-explainer (ExplainerShell with chapterNav, the trust-map components). Mode: Read.
Audience: a developer new to the change, and readers outside the team. Job: understand how it works and how each claim about it is verified. Constraints: data comes only from derived values; no page CSS; no-JS pre-render readable; ISO host palette kept so decks, posters and charts do not change.

## Direction contract
THESIS: A field guide to one PR. Each level is a question heading with a plain-words answer first, then a figure, then detail behind labelled openers. It refuses the audit dashboard: stacked pills, rules and amber paragraphs at one density.
OWN-WORLD: ISO host kept (white or lifted near-black ground, one cyan accent for the current thing). New: an embedded pairing (Source Serif 4 prose, IBM Plex Sans rows and controls, IBM Plex Mono code); one 4px-based spacing scale; an 18px reading column capped near 64 characters; two weights (400, 600); quiet light code plates in light mode; one mark language (check, half, warning, cross glyphs in tone pills) shared by verdicts, bars and control results; countable square marks for every "N of M".
STORY: A verification explainer. The reader sees what the change promises with one worked example, then one run through the numbered stations, the invariants, how to read the evidence, and each claim with its checks, planted bugs, proofs and code.
FIRST VIEWPORT: Title and one-line summary; the plain-words lead; the first worked example with its stations. Chapter rail left at 1200px and up with the "you are here" marker; sticky top bar below.
FORM: field guide with numbered stations (own list position 4), fused with the question ladder (5) and the textbook chapter lead (1). Seed key 15e18c7c.
FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
