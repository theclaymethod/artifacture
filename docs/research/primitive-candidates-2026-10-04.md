# Additional visual and motion primitives

Research snapshot: 2026-10-04. Start with source-range code focus, matched equation terms, and chart geometry that can enter the shared scene model. They add teaching capabilities the current catalog lacks. Add a beat compiler to reduce repeated timing work. Keep arbitrary shape morphing and spring motion as experiments until their actual browser exports survive backward seeking.

This is a candidate list, not an implementation receipt. API sketches below are proposed names. No dependencies, source modules, or tests were added for this research.

## What is already available

The local contracts establish the following boundary:

| Available now | Material limit |
| --- | --- |
| [GraphicScene](../../visual-explainer-mdx/graphics-types.ts): rectangles, circles, polygons, paths, lines, text, semantic paint/font/stroke roles, IDs, bounds, placement, clipping | No equation-term matching, data marks, camera track, or geometry interpolation contract. |
| [Finite motion](../../visual-explainer-mdx/graphic-motion.ts): opacity, path reveal, highlight, illustration translation; linear and smooth easing; direct sampling | Reveal requires path-only objects. Translation accepts illustration objects. Highlight becomes a boolean at the midpoint, so it is a focus change rather than a continuous color tween. |
| [Composition](../../visual-explainer-mdx/graphics-composition.ts): uniform fitting, scoped IDs, nested placement/clip resolution, one clock | No public attachment ports or connections between separately composed scenes. Do not add another general group renderer. |
| [Diagrams](../../visual-explainer-mdx/diagram-scene.ts), [Hairline path adapter](../../visual-explainer-mdx/hairline-scene.ts), [slide sequences](../../visual-explainer-mdx/graphic-slides.tsx) | The Hairline adapter accepts prepared silhouette/crease paths; it does not produce solids or run the native pointer engine. Slide sequences already supply finite slots and holds. |
| [Five Lieflat encodings](../../visual-explainer-mdx/lieflat-charts.tsx): rung bars, unit fields, barcodes, bubble matrices, threads | These render through React, measured host width, and local selection state. They do not yet return GraphicScene geometry or sample data changes through the authored clock. Preserve exact fractions, missing data, units, and accessible tables when extracting geometry. |

The [weighted-neuron and sigmoid example](../../examples/visual-explainer-mdx/math-activation.tsx) already demonstrates math text and a sampled curve. A reusable parameterized plot builder and matched equation parts would extend that example. Hairline, 3b1b, Mono Color, and Algebrica should all consume the same geometry; [shared themes](../shared-themes.md) continue to own appearance.

## Prioritized candidates

This order reflects fit with the requested code-review and technical/nontechnical explanation modes, and the size of the missing local contract.

| Order | Candidate | First teaching use | Decision |
| --- | --- | --- | --- |
| 1 | Source-range code focus and change pairs | Explain a bug, its correction, and the affected system | Prototype next |
| 2 | Matched equation terms | Show which terms survive an algebraic step | Prototype next |
| 3 | Chart mark geometry and keyed data states | Make a chart change without losing record identity | Prototype next |
| 4 | Teaching beats and causal flow traces | Reveal a dependency, then its consequence | Compile existing motion first |
| 5 | Parameterized axes and curve probes | Change one input and observe a function | Build on chart geometry |
| 6 | Scene attachment ports and authored framing | Explain a subsystem while retaining its place in the whole | Extend existing composition |
| 7 | Projected solids and exploded layers | Explain software or device layers in Hairline | Bounded geometry experiment |

| 9 | Finite spring settling | Give a state change weight when settling has meaning | Seekability experiment |

### 1. Source-range code focus and change pairs

**Evidence.** Motion Canvas exposes code-range selection and timed code editing. Code Hike separates line/block annotations from token/column annotations; its focus example dims other code and keeps focused lines in view. These are precise source anchors, rather than invented captions. [Motion Canvas Code](https://motioncanvas.io/docs/code/), [Code Hike annotations](https://codehike.org/docs/concepts/annotations), [focus](https://codehike.org/docs/code/focus).

**Local fit.** Propose `createCodeScene({ source, revision, ranges, frame })` with stable line/token IDs, and a `changePair` containing actual before/after text. Render mono text and one focus accent. A source anchor may connect to a diagram object's ID. Keep DOM scrolling in the interactive docs adapter; exported frames need an explicit sampled viewport. Port the selection contract first, rather than adopting a second generator-based animation engine.

**Smallest proof.** Explain one real three-line bug fix beside its diagram. Seek directly to before, focused change, and after in both directions. Inspect a narrow layout with a long line, duplicate tokens, and an absent source range. Verify the original code is readable/copyable and the selected range matches the actual revision. Source and demo snippets need recorded ownership; copied library code carries the MIT notices listed below.

### 2. Matched equation terms

**Evidence.** Manim's `TransformMatchingTex` matches subobjects by `tex_string`, accepts `key_map`, and provides mismatch policies. `TransformMatchingShapes` instead compares normalized point-coordinate hashes. These are different matching strategies, not a guarantee that arbitrary glyphs morph cleanly. [Matching TeX](https://docs.manim.community/en/stable/reference/manim.animation.transform_matching_parts.TransformMatchingTex.html), [matching shapes](https://docs.manim.community/en/stable/reference/manim.animation.transform_matching_parts.TransformMatchingShapes.html).

**Local fit.** Propose `matchTerms({ from, to, matches })`: authors name term IDs and explicit pairings. Start with existing Unicode/STIX math text. Move preserved terms, introduce new terms, and remove old terms using finite tracks. Text equality alone is insufficient when an equation repeats `x` or `1`. This needs a prepared layout and a geometry/placement transition; today's opaque text primitive does not expose mathematical subparts. A browser port of the matching idea fits the source-copy model. Full Python Manim remains a separate renderer option.

**Smallest proof.** Transform `a + b = c` into `a = c − b`, preserving three term identities and handling the changed operator. Add one repeated symbol, compare narrow/wide layouts, and export a poster at the intermediate state. TeX parsing, glyph outlines, fractions, and automatic algebra are later questions; separately check font and asset rights if those are introduced. Manim code is MIT.

### 3. Chart mark geometry and keyed data states

**Evidence.** Observable Plot composes marks bound to data channels and shared scales. D3's line generator returns SVG path data when no drawing context is supplied; `defined` breaks lines at missing observations. This supports geometry helpers without importing D3 transitions or Plot's DOM renderer. [Plot marks](https://observablehq.github.io/plot/features/marks), [D3 line](https://d3js.org/d3-shape/line).

**Local fit.** Extract `marks({ data, scales, frame })` into objects with stable record IDs. Begin with dot, line, rule, label, and the existing rung encoding. Propose `sampleDataState({ from, to, keys, domains }, t)` separately from rendering. New/deleted records need explicit entry/exit policies. Keep comparable domains fixed; an intentional domain change must be shown. Interpolate quantitative values, never categories or missing data into fabricated measurements. Preserve the existing Lieflat React tables and controls around the same geometry.

**Smallest proof.** Animate a three-category rung comparison with a fractional value and a missing value. Reuse the same sampled scene as a diagram inset, a poster, and a video frame. Verify exact endpoints, record identity, thin Hairline strokes, and unchanged quantitative meaning in all four themes. D3 Shape and Observable Plot use ISC licenses; their notices accompany copied implementation.

### 4. Teaching beats and causal flow traces

**Evidence.** Manim's `LaggedStart` schedules delayed animations within a total runtime; `MoveAlongPath` moves an object along another object's path. The local notes from the user's motion article emphasize explicit story states and direct frame sampling. The article was read in the earlier browser investigation, not reread or treated as executable code here. [LaggedStart](https://docs.manim.community/en/stable/reference/manim.animation.composition.LaggedStart.html), [MoveAlongPath](https://docs.manim.community/en/stable/reference/manim.animation.movement.MoveAlongPath.html), [local article receipt](../video-production-references.md), [original article](https://x.com/0xwhrrari/status/2105643919119696297).

**Local fit.** Propose `compileBeats(scene, [{ at, reveal, focus, hold }])` returning existing GraphicMotion tracks. Start with a compiler, not another clock. A later `flowTrace` can use a prepared path and arc-length samples to locate a packet at progress `p`. Path reveal explains that a relationship exists; a moving packet explains traversal. They should remain separate operations. An arrow already implies direction, so another arrow or caption is unnecessary.

**Smallest proof.** Show a request crossing three stages, with the next stage appearing only after its dependency is established. Compare the compiled result with the manually authored tracks at the actual reading holds and after a backward seek. For a flow trace, use one curved edge and verify constant-distance progression rather than uneven parameter speed. Manim reference code is MIT; write original narrative and geometry.

### 5. Parameterized axes and curve probes

**Evidence.** Mafs supplies function, parametric, and vector-field plots. `Plot.Parametric` accepts `xy(t)` and a domain; its documentation notes numerical sampling limits. `useMovablePoint` supports side-effect-free constraints, including horizontal/vertical motion and custom snapping. [Plots](https://mafs.dev/guides/display/plots), [movable points](https://mafs.dev/guides/interaction/movable-points).

**Local fit.** Propose `createPlotScene({ axes, samples, probe })` using the scales and path helpers from candidate 3. Keep callable functions in authoring code; save finite sampled data and parameter values in the portable scene. A slider and video parameter track should select the same data-space value. Teach slope, saturation, distributions, and optimization by moving a probe or changing one parameter, rather than drawing an unrelated decorative curve.

**Smallest proof.** Turn the existing sigmoid into a parameterized plot with a constrained input probe, then introduce a discontinuous function to settle gap handling and sample limits. Compare endpoints, axes, probe labels, and backward seeking across aspect ratios. Mafs is MIT; a local helper can copy its API idea without shipping its React interaction runtime or upstream examples.

### 6. Scene attachment ports and authored framing

**Evidence.** React Flow's `parentId` gives a child parent-relative coordinates; `extent: 'parent'` constrains its extent. This does not create actual nested DOM markup. Motion Canvas's camera API separates `centerOn` and `zoom`, and cautions against manipulating camera scale directly. [React Flow sub-flows](https://reactflow.dev/learn/layouting/sub-flows), [Motion Canvas camera](https://motioncanvas.io/docs/camera/).

**Local fit.** Reuse `composeGraphics` for grouping and fitting. Add an authored port map, such as `{ name, objectId, anchor }`, whose coordinates are resolved through placement before routing cross-scene edges. Propose a separate finite viewport track for framing; it must not resize semantic geometry or invalidate connection endpoints. Static posters choose one frame. Docs and video sample a frame. Avoid a generic mutable scene tree or live layout-animation engine.

**Smallest proof.** Compose a three-node subsystem twice, connect one outer edge to a named port, then frame one instance and return to the overview. Inspect clipping, readable labels, scoped identities, correct port coordinates, and repeated seeking. Use explicit wide/portrait frames instead of cropping a wide composition. Both reference engines are MIT; imported logos and product assets require their own provenance.

## Experiments before catalog inclusion

### 7. Projected solids and exploded layers

Hairline's upstream figures include layered windows/devices, branch history, and patch panels. Its native geometry index exposes camera projection and `prism(...) → { sil, crease }`; the current local adapter already consumes this shape. Use the unchanged pinned engine to prepare geometry, then author an explicit parameter/state adapter around it. [Hairline repository](https://github.com/lucasmarkes/hairline), [local kernel API index](../../plugins/visual-explainer/vendor/hairline-create/kernel.js), [pinned provenance](../../plugins/visual-explainer/vendor/hairline-create/provenance.json).

The smallest useful experiment is one three-layer stack with an authored separation parameter, a selected layer, and a labeled diagram connection outside the native illustration. Reproject each state from its parameters and preserve back-to-front ordering. Sample rest, halfway, and fully separated states before and after a backward seek. This exposes occlusion and frame-fit questions. Do not replay pointer events or transplant the native `stepS` spring into offline exports. The current upstream repository has expanded figures; that does not update the local pin automatically. Hairline is MIT; preserve its unchanged runtime and notices when bundled.

### 8. Shape/path transforms

Flubber's `interpolate(fromShape, toShape, options)` returns a function of progress from zero to one. It accepts SVG paths or rings and exposes a segment-length/performance tradeoff. Its documented single-shape interpolation ignores holes and other outer shapes. This makes it a limited experiment, especially for Hairline silhouettes plus creases. [Flubber API](https://github.com/veltman/flubber).

Start with same-kind numeric geometry changes, or explicitly matched polygon vertices. Propose `morphPath` only for a validated topology. The proof is a circle-to-rounded-rectangle transformation with endpoint equality, repeated seeking, a contour containing a hole that must be rejected, and a silhouette/crease case that must retain meaning. A visual representation change should explain something, such as one unit becoming a grouped quantity. Do not make arbitrary crossfades look like mathematical continuity. Flubber is MIT; its reference does not establish performance or correctness for this repository.

### 9. Finite spring settling

Motion's low-level `spring({ keyframes, ... })` returns a sampler whose `.next(milliseconds)` supports out-of-order times. Direct `duration` uses milliseconds, while `visualDuration` uses seconds. Its docs warn that zero damping can oscillate forever. This is a stronger seekable API reference than a step-by-step simulation. [Motion spring](https://motion.dev/docs/spring).

Propose one `settle` track with an explicit finite slot, units, initial velocity, damping policy, and exact final hold. Reject nonfinite parameters and endless configurations. Do not use spring progress for opacity or reveal: overshoot can leave their valid zero-to-one ranges. First demonstrate a translated illustration landing in a frame; sample late, early, late again, and after its slot. Compare browser render/export output and clipping. Keep smooth easing as the default until this succeeds. Motion's open-source code is MIT; this proposal uses that sampler, not paid Motion+ examples or APIs.

## Exclude from the primitive catalog

Do not add aliases for fades, wipes, or staggers that merely wrap current tracks; a beat compiler covers repeated scheduling. Do not duplicate composition with a second grouping system. Avoid idle wobble, glow trails, perpetual particles, gratuitous camera motion, ornamental labels, and physics with hidden clock state. A native Hairline pointer demo can remain interactive, but it is not automatically an authored video primitive. Keep automatic algebra, arbitrary TeX morphing, general force simulation, and full 3D cameras outside the first prototypes.

### Fields and masks from Shader for Interfaces

**Checked source.** Its data reference describes regular scalar grids, attributed point clouds, vector fields, density estimates, and temporal surfaces. It requires explicit domains, units, missing-value handling, and accessible alternatives. The GLSL reference covers antialiased analytic edges with `fwidth`/`smoothstep`, normalized coordinates, stable uniforms, and bounded time. These are techniques, not supplied `ScalarGrid` or `ThresholdMask` exports. [Data reference](https://github.com/v2space-labs/shader-for-interfaces/blob/08fe6fc1dad56fcdf29b967c3d5d65966bdac860/references/data-visualization.md), [GLSL patterns](https://github.com/v2space-labs/shader-for-interfaces/blob/08fe6fc1dad56fcdf29b967c3d5d65966bdac860/references/glsl-patterns.md).

The following APIs are **proposed adaptations**. Small datasets should return ordinary scene geometry first; adding a GPU renderer is an independent experiment.

| Proposed block | Input → output | Teaching use and theme fit | Smallest proof |
| --- | --- | --- | --- |
| `ScalarGrid` | Grid dimensions, values, domain, units, missing mask → stable cell rectangles or projected pillars | Explain a heatmap, activation surface, or spatial comparison. Hairline uses thin outlines and one accent; Mono Color uses one hue with a declared magnitude scale. Algebrica/3b1b can connect cells to equations or probes. | A 4×4 grid with a missing cell and an out-of-domain value; preserve meanings at two sizes and two sampled states. |
| `VectorGlyphField` | Sample positions, vector components, unit/length scale → arrow paths with stable sample IDs | Show gradients, forces, or flow direction. Separate vector magnitude from movement speed. Use the same thin paths in all themes; 3b1b is a natural mathematical presentation. | A 5×5 field including a zero vector. Change a parameter, then seek backward to verify direction, length, and identity. |
| `ContourBands` / `ThresholdRegion` | Scalar grid, explicit thresholds, frame → contour paths or a highlighted region | Explain decision boundaries, elevation, or probability levels. Hairline can use contour outlines; other themes can use neutral bands with one selected accent. | Two peaks and one hole. Compare the contour against its threshold and preserve holes after composition. |
| `SeededPointField` | Seed, finite count, predetermined birth/death times, analytic position function, authored time → circles or short paths | Show a bounded population or transport sample. This is an illustration unless points represent actual records. Keep record identity when they do. | Twelve points at late/early/late times; reproduce positions without replaying frames. |
| `TextureLens` | Owned image, normalized crop, bounded displacement, authored progress → raster surface | Explain a lens or image transformation only when distortion teaches the concept. A static image is its poster state. It is an experiment for all four themes, not a background effect. | Check exact unwarped endpoints, edge sampling, aspect ratios, failure fallback, and a directly sampled intermediate frame. |

For contours there is a real importable alternative to writing an algorithm: D3's `contours().size([columns, rows]).thresholds(levels)(values)` returns planar GeoJSON MultiPolygons with their threshold values. Its input is a flat scalar grid, not latitude/longitude. The local adapter would convert those rings into paths; D3 supplies geometry without an animation clock. [Contour API](https://d3js.org/d3-contour/contour), [ISC license](https://raw.githubusercontent.com/d3/d3-contour/main/LICENSE). This dependency has not been installed.

The particle reference recommends stable seeded initialization, retained buffers, and bounded work; it does not supply an authored-time particle solver. The texture reference supplies crop/cover and edge-sampling guidance, rather than a ready lens component. Our seekable analytic position contract is an adaptation. [Particle reference](https://github.com/v2space-labs/shader-for-interfaces/blob/08fe6fc1dad56fcdf29b967c3d5d65966bdac860/references/particles.md), [texture reference](https://github.com/v2space-labs/shader-for-interfaces/blob/08fe6fc1dad56fcdf29b967c3d5d65966bdac860/references/textures-and-distortion.md).

`GraphicPrimitive` currently has no image, canvas, or shader member. A raster/GPU surface therefore needs an explicit renderer and export contract; it cannot be cast into the SVG union. A future surface must accept authored time and seed, declare dimensions, preserve text/controls outside the effect, expose a static fallback, and signal an actual rendered frame. Begin with geometry so the same scene already travels through composition, slides, and video. Shader for Interfaces itself excludes feedback simulations and multi-pass render graphs from its scope. [Upstream scope](https://github.com/v2space-labs/shader-for-interfaces/blob/08fe6fc1dad56fcdf29b967c3d5d65966bdac860/SKILL.md).

### Maps and routes from prettymaps

**Checked source.** `prettymaps.plot(...)` returns `Plot` containing layer GeoDataFrames, Matplotlib figure/axis, background geometry, and keypoints. `PolygonPatch` handles exterior/interior polygon rings. `transform_gdfs` projects for its transforms, then returns EPSG:4326 coordinates. Palette drawing uses an unseeded random choice. These details mean a browser import must explicitly project, preserve holes, and assign stable theme roles. [Drawing implementation](https://github.com/marceloprates/prettymaps/blob/02f85870ced807b7d24ce1764764ff877f9edffd/prettymaps/draw.py).

`read_track(...)` accepts GPX/KML paths and returns a longitude/latitude MultiLineString or no track. `track_center` and `track_radius` help derive fetch bounds. This is a usable Python ingestion API, not a browser module. [Track parser](https://github.com/marceloprates/prettymaps/blob/02f85870ced807b7d24ce1764764ff877f9edffd/prettymaps/gpx.py). The tutorial also demonstrates layered presets, keypoints, hillshade, and plotter SVG export. [Tutorial](https://github.com/marceloprates/prettymaps/blob/02f85870ced807b7d24ce1764764ff877f9edffd/docs/tutorial.md).

The next blocks are **original browser-adapter proposals**, not copied prettymaps source:

| Proposed block | Input → output | Teaching use and theme fit | Smallest proof |
| --- | --- | --- | --- |
| `MapLayers` | Frozen GeoJSON, projection, frame, semantic layer order → paths grouped by stable feature IDs | Reuse water, roads, parcels, and building footprints as an explanatory map. Hairline uses fine strokes; the other themes change paint roles, not geography. | An original miniature map with one building courtyard and a water boundary; fit wide/portrait without filling the hole. |
| `RouteTrace` | Frozen route coordinates, projection, progress, optional real timestamps → revealed path and marker position | Explain journeys, packet traversal through a mapped system, or changes in a route. One accent identifies the active path in every theme. | A three-segment route with unequal lengths. Compare constant-distance and timestamp-based progression and label which meaning is used. |
| `FeatureAnchor` | Feature ID, named anchor, optional authored label position → point/label plus composition attachment coordinates | Connect a geographical place to a diagram or equation. Labels identify necessary places; avoid an automatic forest of names. | Connect one map location to an existing diagram port; verify both positions after fitting and clipping. |
| `BoundaryRegion` | Outer ring, interior rings, frame → reusable outlined/filled region | Explain a catchment, service area, or selected subset. Hairline should retain thin borders and empty interiors; no decorative frame around every map. | A polygon with a hole and a disjoint island; inspect fills and nested composition. |

Freeze fetched data before video rendering and record source, bounds, CRS, and retrieval date. Feature projection and theme assignment happen once; authored tracks then reveal or focus existing geometry. Returned EPSG:4326 coordinates must never be interpreted as scene pixels. General polygon clipping and fill-rule handling remain open local contracts: `GraphicClip` supports rectangles, while filled compound paths need consistent ring winding or an explicit fill-rule extension.

The optional upstream Python exporter is materially larger than a copied browser block. Its checked package requires Python 3.12+ and pulls a geospatial/render stack including OSMnx, Shapely, Matplotlib, raster tools, OpenCV, and vsketch. [Package metadata](https://github.com/marceloprates/prettymaps/blob/02f85870ced807b7d24ce1764764ff877f9edffd/setup.py), [dependencies](https://github.com/marceloprates/prettymaps/blob/02f85870ced807b7d24ce1764764ff877f9edffd/requirements.txt). Keep an upstream exporter pinned with its license notices if used. Do not include AGPL implementation in the default MIT source-copy closure. Separately, OpenStreetMap data is ODbL and requires attribution; output provenance must distinguish data rights from program licensing. [OpenStreetMap license and attribution](https://www.openstreetmap.org/copyright). No upstream pictures, map datasets, or output assets were imported.

### Two bounded implementation picks

**Narration cues shared by captions and subtitles.** Lemo's `core/render/srt.py` sorts `{t0,t1,text}` cues, truncates an overlap at the next start, and formats timestamps by rounding the entire millisecond count before splitting hours/minutes/seconds. Its `styles/dataviz/demo/film.js` exports `setCaptions(lines, dur, words)` and `subs()`: line-relative word times become absolute times by adding each line's `t`; the same caption intervals supply subtitles. These are small, concrete donor implementations. [SRT conversion](https://github.com/lemomo-ai/lemo-opuscar/blob/54be47b14f2ecb2e7c5f473c934db8de0235b795/core/render/srt.py), [caption assembly](https://github.com/lemomo-ai/lemo-opuscar/blob/54be47b14f2ecb2e7c5f473c934db8de0235b795/styles/dataviz/demo/film.js#L208).

Propose a dependency-free `normalizeNarrationCues(...)` leaf returning immutable absolute-second cues and word ranges, plus `formatSubtitleTime(...)`/SRT/VTT serialization. Inputs include line ID, display text, actual audio duration, global start, optional measured words, and an explicit overlap policy. Keep transcript words distinct from display tokens: spoken numbers or abbreviations can differ from code/math typography. Retain an alignment source and distinguish measured timing from estimated fallback. Do not silently stretch a measured word boundary onto a beat. One compiled cue result should drive DOM/SVG captions, exported subtitles, narration placement, and visual focus events on the existing clock. Preserve the LemoLab MIT notice when adapting source.

**Real alignment data exposes a boundary case.** `core/tts/asr_check.py` calls faster-whisper with `word_timestamps=True`, pads audio by 0.6 seconds at both ends, then writes `{lineId: [[word,start,end],...]}` after subtracting the pad. The checked dataviz `voices/words.json` contains starts at −0.6 seconds; `words_rel.json` instead uses `{w,t}` and adjusts some tokens. Those schemas cannot be passed interchangeably. [ASR implementation](https://github.com/lemomo-ai/lemo-opuscar/blob/54be47b14f2ecb2e7c5f473c934db8de0235b795/core/tts/asr_check.py#L104), [raw alignment](https://github.com/lemomo-ai/lemo-opuscar/blob/54be47b14f2ecb2e7c5f473c934db8de0235b795/styles/dataviz/demo/voices/words.json), [display timing](https://github.com/lemomo-ai/lemo-opuscar/blob/54be47b14f2ecb2e7c5f473c934db8de0235b795/styles/dataviz/demo/voices/words_rel.json).

The smallest proof uses original narration with punctuation, a spoken number, an intentional pause, one negative padded start, and an overlapping cue. Validate finite times, duration bounds, stable ordering, missing line IDs, and the chosen overlap behavior. Inspect a directly sought caption against the actual audio, then compare SRT/VTT endpoints. Timestamp serialization should carry `1.9996` seconds into the next second. No voice engine is needed to prototype the adapter: accept measured output from the existing Ainthony pipeline. A new alignment engine is optional tooling, not a change to the requested voice.

**Monotone scalar/vector keyframes.** `core/lib.js` exports `monotone(keys)` for `[seconds,value]` pairs and `track(keys)` for `[seconds,number[]]` pairs. It precomputes cubic tangents, limits slope magnitudes, and holds endpoint values outside the key range. Sampling does not advance a clock or require previous frames. Its inputs are unchecked; empty keys, repeated times, and inconsistent dimensions need a wrapper. The neighboring `spring(...)` lacks a finite slot and should not be adopted as a finished motion contract. [Actual helper implementation](https://github.com/lemomo-ai/lemo-opuscar/blob/54be47b14f2ecb2e7c5f473c934db8de0235b795/core/lib.js#L18).

Adapt only the needed sampler into the current motion/authoring layer, with finite values, nonempty keys, strictly increasing seconds, and equal vector dimensions. Use it for a camera center or a parameter through several authored states, where segment continuity matters. It does not make a categorical or missing chart value interpolatable. Prototype increasing/decreasing segments, a plateau, a reversal, and late/early/late sampling; inspect the actual scene at key times and within each segment. This JS leaf has no runtime dependencies. Preserve its MIT notice and avoid duplicating existing clamp, lerp, or smooth easing helpers.
