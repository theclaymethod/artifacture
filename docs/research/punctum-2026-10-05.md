## What is useful

Punctum is a variable dot-matrix typeface and a collection of film sources. The glyph data is especially compatible with the shared primitive approach: each character occupies five columns and nine rows, including two descender rows. A glyph can become editable circle or rounded-rectangle geometry rather than a captured image. The font's `wght` axis controls dot size over 100–900; `ROND` controls round-to-square shape over 0–100.

## Approved blocks

1. **Dot-matrix glyph scene.** First priority: return GraphicScene data with stable glyph/cell identities, explicit text, dot pitch, and round/square geometry. Theme paint roles own the neutral cells and one meaningful accent. A chosen sample becomes a poster or diagram; the same geometry enters composition, slides, and video. An unlit lattice is optional when explaining the display's structure.
2. **Finite character roll.** Prepare old and new messages in a common grid, with authored start, completion, stagger, and an exact final text state. Compile changes into GraphicMotion or an explicit-time model sampler. Intermediate drum characters are a display transition, not measured values; do not use them as factual chart annotations. Preserve unchanged characters and provide a stationary final state for reduced motion.
3. **Column scan with optional sound events.** A playhead reads a glyph or binary matrix by column; the visible cells produce named events on the same clock. This can explain encoding, quantization, or a sequencer. Sound should demonstrate that relationship and remain subordinate to narration.
4. **Optional variable-font readout.** Use the canonical WOFF2 for short display text, with caller-supplied axis values. Await font readiness before capture. Keep ordinary prose, source code, captions, and mathematical notation on their existing font roles.

The first three belong to the scene/motion catalog, not another art theme. Hairline can use neutral fine dots on white with one contrasting focus; Mono Color can show a restrained readout; 3b1b can demonstrate discrete state changes; Algebrica can frame a glyph or sampling explanation within its existing typography. The upstream amber/VFD/LCD palettes and ornamental film readouts do not become default styles.

## Initial prototype evidence

An inline Node/Vite SSR probe read the pinned JSON and used the real local `createGraphicScene`, `defineGraphicMotion`, and `sampleScene` modules. It confirmed:

- All 108 masks have nine rows of five `.`/`#` cells; all five expected lowercase descenders occupy the extra rows.
- One fixed 45-position scene changes a zero into a one through 19 opacity tracks, with the exact target mask at completion.
- Sampling the endpoint and then seeking backward reproduces the earlier snapshots exactly; prepared scene data is immutable.

This proves a small geometry/clock fit, not rendered quality, a complete split-flap implementation, variable-font animation, audio alignment, or GPU portability. The SSR probe triggered Vite discovery of an unrelated Mermaid violation fixture; the probe itself passed. No upstream renderer, score generator, installation command, or model download was executed. No new test files were created.

The upstream recordings are useful review references: [35 Lights](https://sundyme.github.io/punctum/media/35-lights.mp4), [Specimen](https://sundyme.github.io/punctum/media/specimen-demo.mp4), and [Premiere](https://sundyme.github.io/punctum/media/premiere.mp4). Their appearance was not evaluated by this source probe.

## Approved implementation

The four display blocks now have public registry entries, source-copy closures, a four-theme interactive gallery, and a finite shared-composition video source. SVG glyphs require no font loading; the optional readout bundles the canonical WOFF2 and an awaited readiness helper. Column events drive accent pulses and original deterministic WAV synthesis. The complete OFL notice and source hashes accompany every relevant source copy.

Direct probes confirmed 108 masks, five descenders, 161 original roll-change boundaries, and another 864 boundaries across 18 short-tick/stagger combinations. The latter caught a binary-duration overlap, repaired by selecting the immediately smaller representable duration when addition would overshoot an authored boundary. Event times remain unchanged. Endpoint and backward-seek checks passed through the real composition sampler. See [the verification receipt](../verification/punctum-2026-10-05.md) for copy, build, browser, and existing-suite evidence.

## Reuse boundary

The [MIT notice](https://github.com/sundyme/punctum/blob/56caad6cb7295c98fede26edb196d763e124b75d/LICENSE) covers site, film, and tooling code. It explicitly separates font software and its sources, which use [SIL OFL 1.1](https://github.com/sundyme/punctum/blob/56caad6cb7295c98fede26edb196d763e124b75d/OFL.txt). Any copied glyph data, font source, or WOFF2 must carry its own OFL copyright/license notice; do not silently label it as the library's MIT source. Copied film code needs its MIT notice. External voice/audio assets require their own provenance.

The canonical `fonts/Punctum-VF.woff2` differs from older embedded film copies. Select the pinned canonical asset and verify its coverage when a font block ships. The approved implementation now bundles the canonical font, unmodified glyph table, complete OFL notice, and pinned SHA-256 hashes in `visual-explainer-mdx/PUNCTUM-PROVENANCE.md`. Original MIT adapters prepare scene geometry, finite tracks, and generated sound. No upstream shader, renderer, film code, score, music, or recorded film is bundled.
