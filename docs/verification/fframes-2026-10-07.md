# FFrames shared-vector trial — October 7, 2026

FFrames can render Artifacture's existing vector compositions without duplicating primitives in Rust. The opt-in `artifacture fframes` command samples the shared TypeScript sequence through `GraphicCanvas`, resolves native SVG paints and fonts, then creates a pinned Rust project. `--render` reuses a cached Metal renderer, inspects every frame, writes a strip, and encodes MP4.

The existing browser renderer remains the default. This trial verifies silent vector sequences on macOS Metal; it does not establish support for arbitrary HTML/CSS, image/video clips, shaders, narration or captions. Native header text uses explicit newlines and differs from browser wrapping/font weights. The FFrames upstream supports more features than this bridge exposes.

## Actual encoded compositions

All clips were decoded from the resulting MP4s for visual inspection. `ffprobe` confirmed H.264, 1920 × 1080, 30 fps, the expected frame counts/durations, and no audio stream.

The code review retains the same cached zero while changing the condition and highlighting moved/added code. The math clip retains STIX subscripts, weighted edges, equations and a progressively traced sigmoid. The retry sequence retains node geometry, arrowheads, path reveals, focus transitions and three slide boundaries. Native strips and decoded contact sheets were reviewed; these checks do not claim a separate narrative-quality certification.

The first retry export exposed a long explanatory line that the browser normally wraps. Native inspection reported 360 overflowing frames. Explicit newlines repaired the source. Running the production render helper against the original overflowing frame pack correctly failed, retained `inspect.json`, and produced no MP4.

## Timing and build scope

On this machine, the first native release build took 76 seconds. A subsequent prototype rebuild took 7.37 seconds. Building the managed renderer in its separate target cache took 46.71 seconds. These costs are separate from sampling/encoding; the CLI does not install a toolchain or modify shell profiles.

A cached, complete code-review `artifacture fframes … --render` invocation took **8.08 seconds wall time**, including Vite/source loading, export, inspection of every frame, a 12-image strip and encoding. The stage timings above came from the exporter and subprocess wall clock. FFrames internally reported 1.32 seconds for that clip's native render.

HyperFrames 0.8.136 rendered the corresponding browser composition in **12.30 seconds CLI wall time** (10.197 seconds reported pipeline time), excluding the prior HTML export and a separate all-frame inspection. It used its standard quality preset; the native renderer used libx264 CRF 20, medium, animation tuning. HyperFrames used screenshot capture after its installed drawElement fallback. These are single-run observations with different layout and encoder settings, **not an equivalent-quality or general performance benchmark**.

An initial frame pack repeated the full SVG for every frame: 57,530,336 bytes, 3.99 seconds export. Deduplicating identical sampled states reduced it to about 6.6 MB and 2.07 seconds without changing absolute-time sampling. The native program preloads the bank/index before rendering; a cached binary can accept different durations with the same dimensions/fps.

## Behavior and packaging checks

Inline runtime checks exercised all four canonical theme palettes, visible motion changes, exact `0 → 7 → 0` backward-seek equality, resolved CSS paints, private-brand rejection and normalized path reveal conversion (100-unit line, normalized offset 0.5 → 50 units). Repeat export packs were byte-identical. Five malformed/existing-output CLI cases rejected input and preserved existing output bytes. No new test files or fixtures were added.

Native dependencies are pinned to FFrames revision `30b48f3da60040e0fd7c811fdcd5b159e70a5b02` with a transitive Cargo lock. SVG path lengths use `svg-path-properties` 2.1.0. Font files and their OFL notices travel with the generated project; source, sequence, theme, frame-pack, font and lock hashes are recorded. Cached native binaries are published with a staged copy and rename.

`check:fast` passed all 25 existing end-to-end cases, TypeScript, manifests, runtime freshness, component API/copy-closure checks, static exports, finite video exports and integrity checks. Lint and skill validation passed. The rebuilt runtime contains 630 files. A clean local npm install exported, inspected and rendered the code-review example successfully using the cached native renderer. An isolated standalone skill copy also extracted its bundled runtime, installed locked npm dependencies and rendered successfully through the skill launcher. Package inspection confirmed the native CLI, template, Cargo lock, fonts/licenses, guide and bundled runtime are included. No package was published or branch merged.

The comparison page played both 12-second MP4s to completion through the public preview tunnel with zero browser warnings/errors. The math and retry videos loaded with expected dimensions and durations. This preview compares native and browser font/layout differences explicitly.

## Reproduce

```sh
node scripts/artifacture.mjs fframes examples/visual-explainer-mdx/code-review-diffs-video.tsx --out artifacts/my-fframes-trial --render
```

A new output directory is required. Local trial artifacts are ignored at `artifacts/fframes-trial/{final,math-delivery,retry-delivery}`. Source and authoring instructions ship with the package; rendered trial MP4s are preview artifacts.
