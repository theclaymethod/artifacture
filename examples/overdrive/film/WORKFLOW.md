# A native FFrames explanation

The upstream scaffolder supplies the Rust project, media handling, scene API and rendering CLI. Artifacture supplies this story workflow. Keep `Cargo.toml`, `Cargo.lock`, scenes and renderer commands native. The initial multi-scene example belongs to FFrames and needs adaptation before it represents your subject.

Begin with the viewer's question. Show the current behavior, the mechanism that changes it, and the resulting consequence. Keep one visual subject recognizable across scenes. Write the evidence and spoken argument in `story.md`; author timing and geometry in Rust. Use FFrames scenes, native animations, audio and media instead of an intermediate Artifacture scene model.

For ISO illustrations consult ISO Glow, Hairline and iso-figure. Use their native source or reusable media when live APIs do not fit FFrames. Keep one accent for active state and thin neutral outlines. For mathematical mechanisms use Manim output. FrankenManim is an experimental reference; verify actual output support before depending on it.

Install the official FFrames skill for native API and toolchain guidance. Use the generated project's commands for `timeline`, `inspect`, `frame`, `strip`, audio analysis and `render`. Inspect a draft before final rendering. There is no runtime renderer switch: a browser-dependent composition should start from a native HyperFrames project instead.
